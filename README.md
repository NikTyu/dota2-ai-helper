# Dota 2 AI Helper — локальный ИИ-агент

Агент помогает собрать предметы под конкретный матч Dota 2: игрок описывает драфт и ситуацию
обычным текстом («я Phoenix против Huskar и PA, линию проиграл — что собрать?»), агент ищет
данные в локальной базе знаний, вызывает инструменты и отвечает, проверяя каждый названный предмет.

Работает полностью локально: модель `qwen3:8b` (8 млрд параметров) и эмбеддинги `bge-m3` через Ollama.

## Соответствие заданию — вариант А

| Модуль задания | Реализация | Файлы |
|---|---|---|
| **1. Индексация текстов в векторную / графовую БД** | 314 карточек (127 героев, 187 предметов) → **ChromaDB** (эмбеддинги `bge-m3`). Те же карточки → **граф знаний** в SQLite: 314 узлов, ~4400 связей пяти типов | `indexer.py` |
| **2. RAG-пайплайн** | Вопрос → распознавание героев/предметов (в т. ч. сокращений PA, BKB) → векторный поиск карточек + факты из графа (матчапы, контр-предметы, уже отфильтрованные под героя) → обогащённый запрос → ответ LLM | `rag.py` |
| **3. Инструменты по протоколу MCP** | MCP-сервер с 7 инструментами; агент запускает его отдельным процессом (stdio), передаёт модели схемы инструментов и выполняет её вызовы в цикле | `mcp_server.py`, `agent.py` |

Связи графа: `WEAK_AGAINST`, `STRONG_AGAINST` (герой → герой), `BUILDS`, `COUNTERED_BY` (герой → предмет),
`EFFECTIVE_AGAINST` (предмет → герой). Матчапы считаются в обе стороны: враг в моём «Слаб против»
или я в его «Силён против».

Инструменты MCP:

| Инструмент | Что делает |
|---|---|
| `search_knowledge` | семантический поиск по векторной БД |
| `get_hero`, `get_item` | карточка героя / предмета |
| `get_matchups` | опасные и удобные враги по графу |
| `recommend_items` | подбор предметов из базы с проверкой совместимости и игровыми ситуациями |
| `check_items` | проверка: есть ли предмет в базе и подходит ли он герою |
| `save_build_report` | сохранение билда в `build_<герой>.txt` |

## Как агент отвечает

```
вопрос ──► RAG: векторная БД (ChromaDB) + граф знаний (SQLite) ──► контекст
                                                                    │
           ┌────────────────────────────────────────────────────────┘
           ▼
     qwen3:8b ──tool call──► MCP-клиент ──stdio──► MCP-сервер ──► база знаний
         ▲                                              │
         └──────────────── результат инструмента ◄──────┘   (до 6 шагов)
           │
           ▼
     проверка ответа: каждый названный предмет есть в базе, подходит герою
     и встречается в данных инструментов; иначе — один раунд исправления
```

Качество держится на том, что **модель не придумывает предметы**: списки дают детерминированные
инструменты (с фильтром совместимости `compat.py` — например, Phoenix не получает Eye of Skadi против Huskar),
а итоговый ответ проверяется по базе. Если Ollama недоступна, агент отвечает без LLM — подбором из базы.

## Установка

Нужны Python 3.12–3.14 и [Ollama](https://ollama.com).

```bash
cd dota_2_helper
python3.14 -m venv .venv                         # Windows: py -3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt   # Windows: .venv\Scripts\python -m pip install -r requirements.txt
ollama pull qwen3:8b                             # ~5 ГБ
ollama pull bge-m3                               # ~1,2 ГБ
.venv/bin/python indexer.py                      # построить индексы (~30 с; потом — только при изменении базы)
```

Модели меняются переменными окружения `DOTA_MODEL` и `DOTA_EMBED` (например, `DOTA_MODEL=qwen2.5:7b`).

## Запуск

| Что | Команда |
|---|---|
| Веб-интерфейс (драфт + агент) | `.venv/bin/python web.py` → http://127.0.0.1:8000, вкладка «Спросить агента» |
| Агент в терминале | `.venv/bin/python agent.py` |
| Только RAG, без инструментов | `.venv/bin/python rag.py` |
| MCP-сервер для внешнего клиента | `.venv/bin/python mcp_server.py` (stdio) |
| Классический консольный подбор | `python3 main.py` |
| Перестроить индексы | `.venv/bin/python indexer.py --rebuild` |

Во вкладке агента справа видно, как получен ответ: найденные карточки с оценкой сходства, факты из графа,
список инструментов MCP, каждый вызов с аргументами и результатом и итог проверки — удобно для демонстрации
всех трёх модулей.

## Тесты

```bash
.venv/bin/python -m unittest discover tests
```

33 теста: подбор и совместимость предметов (Phoenix vs Huskar без Skadi, Juggernaut, Rubick, Axe, Tinker),
индексация и граф, распознавание драфта в тексте, MCP-инструменты, цикл агента с подменённой моделью
(включая исправление ответа с неподходящим предметом) и режим без LLM. Ollama для тестов не нужна.

## Структура

```
data/            карточки героев (*.txt) и предметов (items/*.txt) — исходные тексты
index/           построенные индексы: chroma/ (векторная БД), graph.sqlite (граф), meta.json
analys.py        разбор карточек
indexer.py       модуль 1: векторная БД и граф знаний
rag.py           модуль 2: RAG-пайплайн
mcp_server.py    модуль 3: MCP-сервер с инструментами
agent.py         агент: RAG + цикл вызова инструментов + проверка ответа
llm.py           работа с Ollama
main.py          детерминированный подбор предметов (используется инструментами)
compat.py        совместимость предметов с героем
situations.py    игровые ситуации и предметы под них
web.py, static/  веб-интерфейс
tests/           тесты
```

## Ограничения

- Карточки локальные и могут не соответствовать текущему патчу.
- 314 карточек — больше ориентира «10–100 текстов» из задания; каждая карточка короткая (1–2 КБ).
- Модель на 8 млрд параметров иногда даёт поверхностные пояснения; списки предметов при этом остаются
  проверенными. Ответ занимает ~30–45 с на ноутбуке с Apple M4 / 16 ГБ.
- Портреты героев и иконки предметов в `static/img/` — © Valve Corporation, используются в учебных целях.
